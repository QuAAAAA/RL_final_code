# repo/train 交接：UnifiedVoice GPT GRPO

## 目前目標

SFT 已經做過了，現在 `repo/train` 的目標只剩一件事：

> **在已 SFT 的 IndexTTS2 UnifiedVoice GPT 上做 GRPO。**

也就是不要再把 toy control-policy 當主線，也不要回頭做 SFT smoke。

GRPO policy checkpoint 應該是你的 SFT 結果，例如：

```text
SFT_CKPT=/path/to/your/sft_unifiedvoice_gpt.pth
```

目前我在 workspace 只掃到這個 GPT checkpoint：

```text
/srv/RL_project/models/IndexTTS_trained/GPTs/trained_200hr_4e_step202000.pth
```

如果這不是你做完 SFT 的 checkpoint，後續 GRPO runner 必須改用你的 SFT checkpoint。

## 真實 GRPO 架構

```text
SFT UnifiedVoice GPT policy
  -> sample K semantic-code responses per prompt
  -> decode semantic codes to wav through IndexTTS2 s2mel + BigVGAN
  -> reward services score wav
  -> group advantage
  -> GRPO clipped loss on generated semantic-code logprobs
  -> optimizer step on UnifiedVoice GPT
  -> save RL checkpoint
```

核心不是訓練 `TinyControlPolicy`，而是訓練：

```text
repo/index-tts/indextts/gpt/model_v2.py::UnifiedVoice
```

## 已確認的可用接口

### UnifiedVoice generation

`UnifiedVoice.inference_speech()` 已可產生 semantic/mel codes：

```text
repo/index-tts/indextts/gpt/model_v2.py
```

它內部呼叫：

```python
self.inference_model.generate(...)
```

而 `repo/index-tts/indextts/gpt/transformers_generation_utils.py` 支援：

```text
return_dict_in_generate=True
output_logits=True
```

所以 GRPO rollout 可以拿到：

- generated semantic code sequence
- per-step logits
- old logprobs

### Decode to wav

`repo/index-tts/indextts/infer_v2_modded.py` 的 inference path 已經有完整 decode：

```text
semantic codes
  -> gpt latent forward
  -> s2mel gpt_layer
  -> semantic codec vq2emb
  -> length_regulator
  -> cfm inference
  -> BigVGAN
  -> wav
```

GRPO 要做的不是重寫 vocoder，而是把這段 decode 邏輯抽成可重用函式，讓 rollout 可以從 sampled codes 產生 wav。

### Reward pipeline

`repo/train/components.py::ComponentHub` 已有 reward services：

- `emotion`: correct `+5` / wrong `-1`
- `vad`: predicted VA vs target `va_01`
- `global_intensity`
- `local_emphasis`
- optional `asr`
- optional `speaker`

`repo/train/dataset.py` 已能從 VA dataset 建 `ControlPlan`，並把 VA `1~9` 映射到 `0~1`。

### GRPO loss

`repo/train/grpo.py` 已有：

- `compute_group_advantages()`
- `grpo_loss()` clipped surrogate

但目前要改成對 UnifiedVoice GPT 的 semantic-code logprobs 使用。

## GRPO 需要新增的東西

建議新增三層，不要一開始就硬套 NeMo RL：

### 1. IndexTTS policy wrapper

建議檔案：

```text
repo/train/indextts_policy.py
```

責任：

- 載入 SFT UnifiedVoice GPT checkpoint。
- 載入 tokenizer/config。
- 準備 prompt conditioning / emotion vector。
- sample `group_size` 個 semantic code sequences。
- 回傳：
  - `codes`
  - `old_logprobs`
  - `response_mask`
  - metadata needed for decode/update

### 2. IndexTTS decoder wrapper

建議檔案：

```text
repo/train/indextts_decode.py
```

責任：

- 從 sampled semantic codes 產生 wav。
- 優先抽用 `infer_v2_modded.py` 既有 decode path。
- 不要重寫 s2mel / BigVGAN。

### 3. UnifiedVoice GRPO trainer

建議檔案：

```text
repo/train/indextts_grpo_train.py
```

責任：

```text
for each sample:
  control = build_gold_control(example)
  rollouts = policy.sample_group(control, group_size=K)
  wavs = decoder.decode(rollouts.codes)
  rewards = ComponentHub.score(...)
  advantages = compute_group_advantages(rewards)
  policy_logprobs = policy.logprobs(rollouts.codes)
  loss = grpo_loss(policy_logprobs, old_logprobs, advantages, mask)
  backward / optimizer.step
  save checkpoint
```

## 最小可行 GRPO smoke

第一個 smoke 不要全 reward 都開，建議只開：

```json
"enabled_rewards": [
  "emotion",
  "vad",
  "global_intensity"
]
```

理由：

- ASR 慢，而且先不是必要。
- speaker reward 可後加。
- local emphasis 依賴更複雜，先等基本 reward loop 穩。

建議 smoke config：

```text
limit=4
updates=1
batch_size=1
group_size=2
max_mel_tokens=128
top_k=30
top_p=0.8
temperature=0.8
```

成功標準：

- 真的從 SFT checkpoint sample semantic codes。
- 真的 decode 出 wav。
- reward services 回傳 reward。
- `grpo_loss()` 對 UnifiedVoice GPT semantic-code logprobs backward。
- 產生新 checkpoint：

```text
repo/train/runs/indextts-grpo-smoke/checkpoints/step_*.pth
```

## repo/RL / NeMo RL 狀態

`repo/RL` 已接過 NeMo RL custom environment，但目前不建議優先走：

- NeMo RL 仍卡 CUDA / deep-ep build。
- NeMo RL config 偏 LLM policy，不是 UnifiedVoice GPT policy。
- 現階段自寫 PyTorch GRPO loop 更可控。

之後若本地 GRPO loop 跑通，再考慮把 UnifiedVoice GPT policy worker 包進 NeMo RL。
